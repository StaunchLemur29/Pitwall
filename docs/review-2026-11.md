# Pitwall review, November 2026

Two parts: where the whole project stands with a recommended order for what's
left, then a UI review. Written after the overnight run (PRs #19 to #33).

## Where it stands

**Done: phases 0 to 2.** Lap recording, track learning, drills, the in-game
CSP app, the cloud hub with the AI debrief, and the time to beat all work.
Several later features are built too: the SF1000 screen (phase 8), the Tools
page (phase 7) and the coach strip (start of phase 3).

Size: about 8,500 lines of Python in the rig service (2,600 of tests), 9,600
in the dashboard, 460 in the CSP app, 300 in the cloud functions and schema.
126 rig tests, 31 dashboard tests, a 21-check harness for the in-game app,
and one real Assetto Corsa recording (Spa) played end to end.

**What's solid**
- The data path: AC → frame → lap → store → analysis. It's well tested, and
  now has an end-to-end test on a real recording.
- Coaching philosophy is consistent: you're compared only with faster laps or
  the optimal run, rewinds never make a best, and unfinished laps still count
  corner by corner.
- The PC and the hub agree: the TS analysis is checked against the Python on
  the same laps.

**What's weak**
- **Very little has been tested on the real rig.** Every feature from the
  overnight run ran only against the demo car and one Spa recording. The
  biggest risk is a gap between demo data and real AC data: the FFB channel,
  tyre temperatures after a teleport, and the SF1000 packets.
- **Only one real recording.** Edge cases on real tracks (the Nordschleife,
  pit exits, Time Shift rewinds, offs) aren't covered by a test. A human replay
  of a real session would fix that cheaply.
- **Merging is fragile.** Combining the overnight branches dropped a CSS
  brace (caught and fixed in #31). Smaller PRs, merged as they're ready,
  would avoid that.
- **rig.py is large** (the live loop, post-lap work, coaching, SF1000 and
  Tools all live in one class). It works, but each new feature makes it harder
  to change safely.

## Recommended order for the rest

1. **Merge #31, then drive.** One session on the real rig: a few clean laps,
   a Time Shift rewind, an off, a drill. Check that the tyres are warm after the
   teleport, the Tools page shows FFB numbers, and the coach strip makes sense.
   Record it (`scripts\start.bat --record ...`) so it becomes a test.
2. **SF1000 screen check.** Firmware, IP, Test, then go through the wheel's
   pages and note what shows and what's blank. Then decide which of
   Pitwall's own values (delta, brake countdown, drill timer) to put on it.
3. **Live tips (phase 3).** The coach strip already picks one focus and each
   lap's biggest mistake. Live tips are the next step: one short tip per lap,
   on a straight, from the same rules. Audio comes after the text version proves
   useful. This is the biggest coaching gain left.
4. **Blind-spot scan and quiz.** The telemetry scan first (it reuses the lap
   review and the mastery grades), then the short quiz on the hub for things the
   telemetry can't show.
5. **Split rig.py.** Move coaching, the wheel screen and the tools into their
   own modules before phase 3 grows it further. No behaviour change. Do it when
   no feature PR is open, to avoid conflicts.

After that: the Nordschleife pack's corner names (needs real track data),
then phases 4 to 6.

## UI review

Screenshots: the side screen at 1080×1920, the analysis window at 1920×1080,
Settings at 1080×1920, all on the demo car.

**Side screen (driving)**
- Good: the corner name, gear and speed are readable at a glance, and the
  road-ahead map with your best lap's line is clear.
- The "In corner" card leaves a lot of empty space under the name. The arrow
  and the name could be bigger, or the card shorter so the map gets the room.
- The bottom strip's labels (BB, ABS, TC, Last, Best) are small and grey.
  They're fine for a glance but hard to read at arm's length. Making them one
  size larger is cheap.
- **Fixed:** the live card's "Optimal" was the best sectors combined, while
  everywhere else "optimal run" means the modelled lap. It's now labelled
  "Best sectors".

**Analysis window**
- Good: "Where the time went" leads, the corner close-up and charts sit side
  by side, and the lap list is always visible.
- Dense at the top: lap picker, compare picker, live card and four big numbers
  all compete. The four summary numbers could drop to two (this lap and to
  beat), with the others in smaller text.
- The lap map gets clipped at the bottom at 1080 high (corner 5's label).
- **Fixed:** after an out lap, the lap card flashed "Out lap" under the new
  lap's running time, which read as if the current lap were the out lap. It now
  says "That was an out lap".

**Settings**
- Clear grouping now that Coaching has its own tab.
- Each checkbox sits under its label, with the hint below, so pages scroll
  further than they need to. Putting the checkbox beside the label would halve
  the height.

## Claude Design: would it help?

Claude Design is a canvas for mockups: you lay out screens as artboards and
try variations. It doesn't produce the React code or know the live data.

**Verdict: not for a wholesale restyle.** The current look is consistent and
readable, and a redesign would touch every widget for little coaching gain.
It *is* useful for one thing: sketching a screen before it's built. Good
candidates are the live-tip card (step 3 above) or a denser analysis header,
where comparing two or three layouts side by side is quicker than
building them. No design system is set up on the account, so it would start
from scratch (or from screenshots of the current UI).
